## Decisions this plan takes

These choices are the plan's own. Each one has a MEMORY record in Task 12, and the preview in Task 13 shows them to Emre.

1. **The dark closing band is the dark paper between two hairline rules** (option B2). The six colours hold no dark tint that passes every pair: on dark gray `#404040`, red scores 1.87:1, so the focus ring and the link rule fail 3:1, and `--ink-soft` text scores 2.76:1. On the dark paper `#15130f` every pair already passes (red 3.35:1, `--ink-soft` 4.95:1, white 18.55:1). The alternative B1 (a `#404040` fill, white text, a white focus ring inside the band) is shown in the preview as question 1 for Emre.
2. **`--cream` keeps its dark value `#ebebeb`.** The Astro `/typography` negative tiles read `--cream` as a light ink in both themes (MEMORY 2026-09-30 negative-tile-cream). The band gets its own dark rule instead of a new `--cream`.
3. **The theme switch lives in `agustos-chrome.js`.** The no-flash part is a one-line inline head script with the site's CSP nonce. Rejected: a second, render-blocking kit file (`agustos-theme.js`), because it adds a request to every page and a fifth file to vendor. Rejected: a server-rendered theme from a cookie, because a static Astro site cannot read it.
4. **The switch label is CSS-driven.** The button holds both labels ("Dark theme" and "Light theme") and CSS shows one, so a Turbo or other body swap needs no repaint and no label flashes. The label names the theme that the button switches to, so the button carries no `aria-pressed` (a pressed state plus a changing name reads twice).
5. **The drawer opens every More by script, not by CSS.** CSS cannot open a closed `details`; `::details-content` shows the content but leaves the state "collapsed" for screen readers and is missing in Safari before 18.4. The script opens each More of the drawer when the drawer opens and marks it `data-agustos-unfold`. Without the script, each More folds as today.
6. **F is a general kit rule, not an IESDesk exception.** Product UI uses the sidebar, or the top menu when it has about ten destinations or fewer. A new screen, `app-top-menu`, is its reference. Why general: ops `decisions/frontend.md` rule 19 says chrome is decided in DESIGN-agustos first; the IESDesk research of 2026-10-03 found that small products keep one flat menu (fewer than 10 places); and an exception for one app would leave the checker and rule 7 wrong for the next small product. So `ops/fleet.md` gets no IESDesk exception.
7. **The screens table keeps its `theme` field, with one value `light-first`** for every row ("light first, dark by choice"). This keeps the shape of `kit.json` and of the checker `SCREENS` table. AG024 no longer reads the field.
8. **`site-header__theme-sun` and `site-header__theme-moon` keep their rules** as deprecated icon classes (agustos.com and both adapters render them). The new switch uses its own `agustos-theme-switch*` classes and needs neither.
