## 2026-09-16 checker-enforces-screens

The build injects the screens table into `check-agustos-ui.py`, beside the token table. Five error rules key on `data-screen`: the page names its screen (AG020), the name is a row (AG021), primary actions inside `<main>` stay within the row's limit (AG022), quotes appear only where the row allows them (AG023), and `data-theme` appears only on product UI (AG024). The repo test that duplicated the count is gone. Both reference adapters carry `data-screen`, and `content-index` is the ninth screen. Why: a rule that only a repo test reads never reaches a consuming site. Rejected: a second implementation of the rules beside the test; a warning, not an error, for a missing `data-screen`. Ops logs it in `decisions/frontend.md` as 2026-09-16 checker-enforces-screens. Reopen only if: a rule needs data that the checker cannot read. Archive: "v6.1.0: the checker enforces the screens table (2026-09-16)".

## 2026-09-15 vanilla-css-no-tailwind

The design system is plain CSS, in this repo and in every consuming site. Layout needs go to the kit layout layer (stack, cluster, grid, band). Why: one stylesheet to maintain, no CSS toolchain per site, and one class vocabulary that the checker can fully verify. Rejected: (A) this repo ships and mandates Tailwind, which couples every site to one Tailwind version and adds Node to the brand repo; (B) each project may add Tailwind with preflight off, which gives two ways to style while the checker reads only one. Ops logs it in `decisions/frontend.md` as 2026-09-15 vanilla-css-no-tailwind. Reopen only if: the layout layer cannot express a real page and an upstream fix fails. Archive: "Vanilla CSS, no Tailwind (2026-09-15)".

## 2026-09-15 two-chromes-per-brand

The kit ships two chromes: a sidebar, and a topbar with a footer. Each brand registers one in `brand/brands.json`: agustos, iesdesk and specquick use the sidebar; pataraz and pld use the topbar. No chrome rule lives outside `tokens/web.css.tmpl`. Why: the live agustos.com ships a sidebar, and a probe of the live site proved the recorded July topbar wrong; registering chrome per brand makes the flagship configuration, not an exception. Rejected: agustos.com as a local exception outside the kit; retiring the topbar. Ops logs it in `decisions/frontend.md` as 2026-09-15 two-chromes-per-brand. Reopen only if: a brand needs a third chrome. Archive: "Two chromes, chosen per brand (2026-09-15)".
