Ağustos Design System

Two places, one rule

The GitHub repository owns the rules. The Claude Design project owns the drawings. Each thing flows in one direction only.

What to do when One-time setup

Who owns what

Before you touch anything, ask which side owns it. The owner is where you edit. The other side only receives a copy.

DESIGN-agustos, the repository

  • Colour, type, spacing, radius, motion tokens
  • The generated UI kit: ui/agustos.css, fonts, starter page, UI-KIT.md
  • The Laz Güneşi symbol and the shared favicon
  • Every brand lockup

Flows repository → Design. Never edited in Design.

Claude Design, the project

  • Page compositions: the website pages, the IESDesk dashboard
  • Explorations and variants tried in the chat
  • Its own React components and specimen cards

Flows Design → repository, into mockups/claude-design/ only. Never into the kit.

The two flows

When this happens, do this

WhenDo
You changed a token, the CSS template, the favicon, or a logo in the repository
  1. Run python3 scripts/build_design_system.py and merge.
  2. In Claude Code, run /design-push. It builds the bundle, checks nothing is stale, shows the file list, and uploads only what changed.
You made a page in Claude Design that you want to keep for the website
  1. In Claude Code, run /design-pull ui_kits/website.
  2. The page, its runtime, and a screenshot land in mockups/claude-design/ with a README row marked pending.
  3. Commit. The page is a saved reference, not a built page.
It is time to build one of those pages
  1. Open the website repository, not this one.
  2. Tell the agent: rebuild the page from mockups/claude-design/ with ui/UI-KIT.md and the kit classes. Do not copy the Design CSS.
  3. Run check-agustos-ui.py until it exits 0.
  4. Change the README row to implemented and record the repository and commit.
A pulled page shows a rule the kit lacks, for example a new spacing value
  1. Edit one of the three sources: tokens/design-tokens.json, tokens/web.css.tmpl, or brand/brands.json.
  2. Regenerate, test, merge.
  3. Run /design-push so Claude Design receives the new rule.
You want to fix a colour or font inside the Claude Design chat Do not. Design holds a copy of the rules. A fix there is lost on the next push. Make the change in the repository and push it.
You want to copy a Design page's CSS into the repository Do not. The kit is generated from the three sources. Pull the page as a reference, and map only the real rule change into a source.

One-time setup

  1. Connect Claude Code to Claude Design. In an interactive Claude Code terminal, type /design-login and approve the prompt. Once per Mac.
  2. First push. Run /design-push. The first run creates agustos-ui/ in Claude Design and uploads the whole kit, the favicon, and the logos.
  3. First pull. Run /design-pull ui_kits/website. The same command accepts a zip exported from Claude Design.

Commands at a glance

/design-login                      once per Mac
/design-push                       repository → Claude Design (kit, favicon, logos)
/design-pull ui_kits/website       Claude Design → mockups/claude-design/
python3 scripts/build_design_system.py --check   must pass before any push
