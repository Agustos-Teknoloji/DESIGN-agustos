Bayilik · Aydınlatma · Mayıs 2026

Işığın mimariyle buluştuğu yer.

2009'dan bu yana Türkiye'nin önde gelen tasarım stüdyolarıyla. Yazan: Emre Güneş, Ağustos Teknoloji.

Ağustos Teknoloji, on iki uluslararası aydınlatma markasının Türkiye temsilcisidir. Soraa, CoeLux, Xicato ve diğer markalarımızla birlikte; mimar, iç mimar, peyzaj mimarı ve aydınlatma tasarımcılarına proje bazında danışmanlık sunuyoruz.

Yaklaşımımız basit: doğru ışık, doğru yerde, doğru zamanda. Bu nedenle her projede spesifikasyon disiplini ve uzun vadeli teknik destek birlikte yürür.

Çalışma Yaklaşımımız

Her proje, mekânın ihtiyaçlarına özgü bir okumayla başlar. Spesifikasyon süreci üç adımda ilerler:

  1. Aydınlatma briefinin oluşturulması
  2. Ürün önerileri ve teknik dosyaların paylaşımı
  3. Uygulama desteği ve devreye alma

CoeLux · Yapay Gökyüzü

CoeLux, mekâna gerçek gökyüzü algısı taşıyan benzersiz bir teknolojidir. Modüller CRI > 95 değeriyle, 240 m2'lik salonlarda 850 lümen/m2 seviyesinde çalışır. CO2 emisyonu konvansiyonel sistemlere göre belirgin biçimde düşüktür.

İyi aydınlatma, fark edilmediği zaman en iyisidir. — Richard Kelly, 1952

Distribution · Lighting · May 2026

Where light meets architecture.

A studio working with Turkey's leading designers since 2009. By Emre Güneş, Ağustos Teknoloji.

Ağustos Teknoloji represents twelve international lighting brands in Turkey. Soraa, CoeLux, Xicato, and others — we work with architects, interior designers, landscape architects, and lighting designers on project-based consultancy.

Our approach is simple: the right light, in the right place, at the right time. Every project requires specification discipline and long-term technical support.

How We Work

Every project begins with a reading specific to the space. The specification process moves through three stages:

  1. Lighting brief development
  2. Product recommendations and technical files
  3. Implementation support and commissioning

05

Token-to-face map

Which family does which job

The 22 tokens, mapped to faces.

Every token in the system uses one of three families. The rule is consistent: editorial work in serif, functional/UI work in sans, code in mono. No token uses more than one family.

Newsreader (Serif)

  • .type-h1page title
  • .type-h2section
  • .type-h3subsection (italic)
  • .type-bodyparagraph
  • emitalic / deck / byline
  • strongbold emphasis
  • alink
  • sub / sup / sinline modifiers
  • .type-blockquoteattributed quote
  • .type-pullquoteeditorial highlight
  • .type-list-olordered list
  • .type-list-ulunordered list
  • .type-dldefinition list
  • .type-figureimage + caption
  • .type-footnotenotes / sources

Source Sans 3 (Sans)

  • .type-h4label / eyebrow / meta
  • cite (in blockquote)attribution coda
  • .type-table thcolumn headers
  • .type-table tddata cells
  • UI labelsforms, buttons
  • UI numeralsstats, dashboards
  • UI buttonsall interactive
  • UI badges / chipsstatus, tags

JetBrains Mono

  • code (inline)technical values
  • .type-code-blockmulti-line code
  • file inputspaths, hex, IDs
