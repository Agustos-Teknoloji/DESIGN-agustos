Records before 2026-09-24 live in [archive/MEMORY.md](archive/MEMORY.md): "Turning point 1" to "Turning point 24" (May to June 2026), then titled entries such as "Vanilla CSS, no Tailwind (2026-09-15)" through 2026-09-16. ## 2026-09-30 design-push-at-session-start

A local Claude Code session pushes the kit to Claude Design on its own. The SessionStart hook in `.claude/settings.json` runs `scripts/sync_claude_design.py status --hook`. It fingerprints the bundle the repository produces now, the version and every file hash but not the commit, and compares it with the fingerprint that `/design-push` records in `.git/claude-design-pushed.json` after a successful push. When they differ and the checkout is on `main`, the session starts with `git pull --ff-only origin main` and `/design-push`, whose approval prompt stays. A feature branch never pushes: Claude Design mirrors released `main`. The check takes about 60ms, never fails a session, and is silent in a cloud session (`CLAUDE_CODE_REMOTE=true`). Why: Emre asked for no manual release step. Claude Design accepts only an interactive `/design-login` made on the machine that pushes, so neither a cloud session nor GitHub Actions can push; a local session can. Emre chose this over a scheduled background job (2026-09-30). Rejected: an hourly job on the Mac, which pushes with no approval and only while the Mac is on; a GitHub Actions push, which would need a copy of Emre's claude.ai sign-in as a secret on a public repository; keeping `/design-push` as a remembered step. Reopen only if: Claude Design offers a token for automated pushes, or Emre wants pushes without opening this repository.

## 2026-09-30 release-tags-on-main

Every release is tagged by `.github/workflows/tag-release.yml` when it reaches `main`, never by hand. On each push to `main` it runs `scripts/release_tags.py --push`, which takes every dated `## [x.y.z]` CHANGELOG section newer than the newest tag and tags `vx.y.z` on the first commit of main's first-parent history where `VERSION` reads x.y.z, the merge that shipped it. It refuses a `VERSION` with no CHANGELOG section. The workflow uses plain git and Python, no third-party action, and runs no tests: the pre-push hook stays the CI. Why: the session that made a release used to push the tag. On Emre's Mac that worked (v6.4.0 to v6.6.0 carry his name), but a cloud session can push its branch and not a tag, so v7.0.0 and v7.0.1 shipped untagged, and the kit's CDN pins and `--update-check` still pointed at v6.6.1. Emre asked for the same automatic flow from a local or a cloud session, with no manual step, and allowed GitHub Actions for this one job (2026-09-30). The repository is public, so its Actions minutes are free; the 2026-09-24 billing block hit the private repos. Rejected: tagging by hand after a cloud release, which Emre ruled out; a `bin/release` script like IESDesk's, which still needs his Mac; retagging old untagged history, which could move tags consumers already pin. Amends 2026-09-25 no-github-actions: Actions still runs no CI here. Reopen only if: the repository turns private and Actions minutes cost money, or cloud sessions gain tag pushes.

## 2026-09-30 states-table-contract

Every interactive state in both themes is a row of the `states` table in `tokens/design-tokens.json`: element, state, kind, and the foreground and background colour keys for light and dark. The build resolves each pair and refuses one below its floor: 4.5:1 for text, 3:1 for graphics (field borders, logos, the focus ring); disabled controls are exempt. The table is published in `ui/kit.json`, `docs/web.html` and the brand guidelines, and `UI-KIT.md` carries the rules in one paragraph (it sits at its 200-line cap). The v7.0.1 rules: in the dark theme a hover dims the ink (`--ink-soft`) instead of turning text red, and the red rule stays; the footer and the closing band are light islands that scope the light colour roles back in; the More menu hover uses the functional gray, not the pale red that belongs to the closing band; the Ağustos logo turns white on hover in the dark theme; a pressed button moves 1px down; a disabled button (`disabled` or `aria-disabled="true"`) turns gray and ignores hover; field borders use `--ink-faint` and placeholders `--ink-soft`. Why: a browser probe of every element in its rest, hover, focus and pressed states found white on light gray (1.19:1) in the dark More menu, dark footer links that vanished on hover (1.00:1), red hover text on off-black (3.35:1), a dark logo hover that did nothing, 1.27:1 field borders, no pressed state, and disabled buttons that still reacted. Emre asked for all the colours of both themes, hover included, to be written down, and approved the fix and the guidelines pages on 2026-09-30. Rejected: a lighter dark-theme red, which adds a seventh colour; white text with the red rule alone on dark hover, which gives no feedback because content links carry the rule at rest; a browser test in the local gate, which needs Playwright on every contributor machine. Amends 2026-09-29 red-identity-black-action (the dark hover rule) and 2026-09-27 guidelines-pdf-own-generator (the PDF is 13 pages: Colour in use and Emphasis join, and Typography shows the thin headings from the registry). Reopen only if a live site shows a state the table does not list, or the dark theme reaches marketing pages.

## 2026-09-29 v7-conventional-reset

The website layer resets to convention in v7.0.0; identity and the engine stay. Emre chose each part from a live before/after preview of agustos.com and iesdesk.com (2026-09-29). Every website, whatever the brand, uses the top menu and a light footer; product UI alone uses the sidebar. The top menu holds at most five items and puts the rest under one `site-header__more` menu ("Daha fazla"), native `<details>`, no JavaScript. The footer is one band: the lockup and one line on one side, one row of social, legal and language links on the other, with no column headings, no repeat of the top menu and no button. The hero opens with a headline, a deck, two buttons (one primary, one secondary) and a trust line; `hero-links` and the `hero-action` aliases are gone. Sections share one spacing (`--section-space`, 72 to 104px) and no dividing rule; card titles carry no underline, since the whole card is the link. The closing band stays pale red. Why: a month of small taste decisions had left the system hard to own; an independent review counted about 55 rules, 1,408 CSS lines and three releases on one day, and found the sidebar and topbar flipping per brand. Emre asked for the safe, conventional choice with minimum work on his side. Rejected: buying a template kit such as Tailwind Plus, which reverses 2026-09-15 vanilla-css-no-tailwind and means rebuilding every adapter; red buttons on marketing sites, tried in the preview and dropped once the logos took the red; a dark footer; a gray closing band. Amends 2026-09-15 two-chromes-per-brand (chrome now follows the screen family and `chrome` leaves `brand/brands.json`), 2026-09-27 memregunes-brand (its seven labels become four plus More, social and legal move to the footer, when it adopts v7) and 2026-09-29 container-owns-edges (card children drop their margins; the card gap owns the space). Reopen only if a website needs more than five top-level destinations that cannot share a More menu, or a brand needs a chrome that is neither the top menu nor the product sidebar.

## 2026-09-29 golden-type-scale

Every text size sits on one scale: the 16.5px body times 1.272, the square root of the golden ratio, so every second step is 1.618: 13, 16.5, 21, 27, 34, 43, 55, 70, 89px. Headings are thin: hero 89px at 300, H1 55px at 300, H2 43px at 400, H3 21px at 500. Four weights remain (300, 400, 500, 600); the wordmark alone keeps 650, and `strong` drops from 700 to 600 to sit with thin headings. `bodyCompact` (15.5px) stays as the one UI size, off the scale. Two radii remain: 6px for controls and 12px for cards and floating menus. Why: Emre compared four heading styles in the preview (large and light, balanced thin, balanced, firm), chose the thin weights, and asked for a golden-ratio reference; the balanced-thin sizes he had picked by eye already sat within 3px of the scale. Ten sizes chosen one by one become one number and one rule. Rejected: the plain golden ratio (16, 26, 43, 70, 113), whose steps jump too far for the web; keeping 104px heroes, which dominated phone screens. Amends 2026-09-29 h3-upright-middle-step: H3 is 21px, still upright, still the middle step. Reopen only if a real page needs a size between two steps that no heading or UI size can serve.

## 2026-09-29 red-identity-black-action

Red is identity and signal, never action. The Ağustos logo is red and turns black on hover; every other house brand's logo is black and turns red on hover. Buttons are black on every surface, marketing and product alike; the dark-theme red-fill primary CTA is removed, and the dark primary simply inverts. One highlighter stroke per page, `<mark class="type-highlight">`, marks one to four words of the main headline on every brand: red at 15 to 20% behind ink text. It never touches links, buttons, numbers, body text or product UI, and the sentence must read the same without it. Bold (600) marks a fact once per paragraph at most; italic marks names and quoted phrases; underline is for links only. Why: Emre asked for a red highlighter and all-red logos; with red buttons as well, a page showed five red elements, so he kept the identity inks, made hover the red moment for house brands, and made buttons black. Each colour then has one job. Rejected: all-red logos for every brand, which blurs the brands and reverses the v3.0 identity decision (archive: "v3.0 — identity ink separates from interaction signal"); red buttons; a red sun with a black wordmark, deferred as a later brand decision. `brand/brands.json` identity inks are unchanged. Reopen only if a house brand needs to read as independent of Ağustos, or if the highlighter appears more than once a page on a live site.

## 2026-09-29 sidebar-bar-scroll-padding

Below 1024px, `html:has(.site-sidebar-bar)` gets `scroll-padding-top: var(--sidebar-bar-height)` (v6.6.1). The new variable is `calc(var(--control-min) + 2 * var(--space-xs) + 1px)`, and the bar takes it as `min-height` in place of its block padding, so the bar and the offset cannot drift. Why: the memregunes speakers review found that the sticky bar covered every anchor target, for example `/organising/#2010-architectural-lighting-day-istanbul`. Consumer sites must not edit `vendor/agustos-ui/`, so the fix belongs in the kit. Rejected: `scroll-margin-top` on targets, because every target needs it; `scroll-padding-top` on every `html` below 1024px, because topbar pages would get the wrong offset; a retyped 61px, because tokens already give the height. A browser without `:has()` keeps the old behaviour. Reopen if the bar gets content taller than 44px, or when the topbar gets the same fix (its sticky header is 85px at every width).

## 2026-09-29 card-stretched-link

A card whose heading holds a link is the target (v6.4.0). The kit stretches a link that is a direct child of the card's `h2`, `h3` or `h4` over the card with an absolutely positioned `::after`. Other links in the card get `position: relative; z-index: 1` and stay clickable. The focus ring moves to the card only inside `@supports selector(:has(a))`, so a browser without `:has()` keeps the ring on the link. The checker warns (AG013) when a card's links all sit outside a heading. Why: hard rule 5 promised the stretched link, but no rule implemented it, so card title links were 22px targets. Emre chose automatic over an opt-in class (2026-09-29), so every consumer site gets it on its next kit bump. Rejected: an opt-in `agustos-card--link` class, which leaves every existing site at 22px until someone edits its markup; and wrapping the whole card in `<a>`, which nests the second link and reads the whole card aloud as one link. The rule is AG013, not AG025, because AG020 to AG024 are screen-rule errors and this is a markup warning. Reopen only if a site needs selectable text inside a linked card, or if a card needs two equal destinations.

## 2026-09-29 bare-elements-share-class-rules

Bare `h1` to `h4` and `p` share the rules of their `.type-*` classes (v6.6.0), as lists, tables, links, code, quotes and rules already did. The selector is the plain element, like `ul, .type-list-ul`, so any class still wins. Why: archive "Vanilla CSS, no Tailwind (2026-09-15)" chose plain CSS because "the kit starts from an on-brand page", and `UI-KIT.md` promised it, but headings and paragraphs rendered in browser defaults. The Astro blog restated the kit by hand to cover the gap, with stale values. A before-and-after comparison of every element on the nine screens and `ui/starter.html` changed only footnotes and form hints (a 12.5px browser margin dropped) and one bare `p`. Emre asked for the best method on 2026-09-29. Rejected: correcting the doc to name only the styled elements, because the vanilla-CSS decision depends on the promise; `:where(h3)` selectors, because the kit already uses plain element selectors and a class wins either way. Reopen only if a consumer needs bare headings unstyled, for example inside third-party widgets. Archive: Vanilla CSS, no Tailwind (2026-09-15).

## 2026-09-29 h3-upright-middle-step

H3 is 22px, upright, weight 500 (v6.5.0), and `.hero-trust` uses `bodyCompact` (15.5px). This amends archive "Turning point 10: Heading distinctness fix", which made H3 italic so that it differed from H2. Why: at that time H2 was small, so italic did the separating. Today H2 is 34px to 52px, so size alone separates the levels, and the 18px italic H3 left no step between body and H2. Card titles, which PR #56 made the label of the whole card, read as small print. ## 2026-09-29 container-owns-edges

A heading that opens a card, a section or a band has no top margin (v6.3.0). The container's padding or gap owns that space. Why: `.agustos-card` and `.agustos-section__head` are flex containers, and flex items never collapse margins, so the Tier 2 section-break margin stacked on the container spacing and left empty bands on every page. Content text uses `--ink-soft`; `--ink-faint` is for non-content marks only, because it scores 3.75:1. Rejected: `.agustos-card > * { margin-block: 0 }`, because it would also remove the bottom margins that separate a card title from its body; and a darker `--ink-faint`, because it would add a new hex. Reopen only if a live site needs the old spacing, or if `--ink-faint` gets a value that passes 4.5:1.

## 2026-09-28 checker-screens-only

`check-agustos-ui.py --screens-only` runs the screen rules (AG020 to AG024) on the rendered `.html` pages of a built site, and nothing else. `UI-KIT.md` tells a consumer whose layout fills `data-screen` at render time to run `check-agustos-ui.py dist --screens-only` after the build. The skipped folders now match only below the scan root, and the screen rules skip a redirect stub (`<meta http-equiv="refresh">`). Why: on an Astro site, `check_screen` returns early on the templated `data-screen={screen}`, and `scan_files` skipped every file under `dist/` because it matched the absolute path. The screen rules ran nowhere, and only the site's own build tests covered the CTA count. Rejected: a documented `dist` step alone, which the path bug made useless; the full rule set on `dist/`, where the kit CSS is bundled under hashed names in `_astro/`, so AG005 and AG006 report false findings and the token rules repeat the source scan; reading the screen name from the Astro source, which ties the checker to one framework; finding the build folder automatically, because the consumer knows its own output folder. Reopen only if: built output holds pages that are not screens and are not redirect stubs, or a whole-project rule needs the rendered output. Archive: none.
